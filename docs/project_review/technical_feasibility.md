# Technical feasibility and architecture audit

## Actual stack and execution

The actual UI is React/Vite on a browser (device); the API and deterministic orchestration are FastAPI/Python on a server; persistence is PostgreSQL in the Compose deployment; geospatial computation runs in Google Earth Engine cloud project `nex-sync`; the scheduler is a separate Python process. The paper’s Streamlit description is a **proposal superseded by the implementation**. Evidence: [Compose](../../compose.yaml), [FastAPI app](../../src/main.py), [frontend](../../frontend/src/pages/Dashboard.jsx), [scheduler](../../scripts/run_scheduler.py).

**Pipeline:** Sentinel-2 surface reflectance `COPERNICUS/S2_SR_HARMONIZED` → SCL cloud masking → monthly median NDVI/NDMI; Sentinel-1 `COPERNICUS/S1_GRD` → monthly median VV/VH; Sentinel-5P `COPERNICUS/S5P/OFFL/L3_CO` → monthly mean CO; all intersected with a 2023 CGMD extent asset and one transboundary envelope. The provider reduces the image over the AOI at 100 m for stored metrics; the map makes Earth Engine tiles; report thumbnails are 1,800 px composites, **not 10 m measured output**. Evidence: [provider](../../src/providers/earth_engine.py), [reporting](../../src/services/reporting.py). Dataset specifications: Google, *Sentinel-2 SR Harmonized* [catalog](https://developers.google.com/earth-engine/datasets/catalog/COPERNICUS_S2_SR_HARMONIZED); Google, *Sentinel-1 GRD* [catalog](https://developers.google.com/earth-engine/datasets/catalog/COPERNICUS_S1_GRD); Google, *Sentinel-5P OFFL CO* [catalog](https://developers.google.com/earth-engine/datasets/catalog/COPERNICUS_S5P_OFFL_L3_CO) (catalog pages, dates not stated). CO is coarse atmospheric-column context, **not local emission or mangrove damage attribution**.

**Dataset suitability:** Sentinel-2 is suitable for canopy greenness at optical resolution where cloud-free coverage exists; Sentinel-1 adds all-weather radar context but needs orbit/angle harmonization; S5P CO is about **1.1 km gridded atmospheric column data** and too coarse for causal local attribution (Google, [CO catalog](https://developers.google.com/earth-engine/datasets/catalog/COPERNICUS_S5P_OFFL_L3_CO)). The CGMD asset is a **30 m annual extent series through 2023**, and code uses its 2023 year as a fixed mask. Its publisher reports about **90% global user's/producer's accuracy** for static extent and about **80% for change**, which may vary locally; it is suitable as a broad screening mask, not an independent truth set or current-loss map (The Mangrove Lab/Google catalog, *Global Annual Mangrove Extent 1984–2023*, date not stated, [source](https://developers.google.com/earth-engine/datasets/catalog/projects_mangrovedatahub2_assets_CGMD-Extent30)). The same publisher offers 30 m annual fractional canopy cover through 2023; this is a relevant benchmark for historic condition, though it does not give current monthly observations (The Mangrove Lab/Google catalog, *Global Annual Mangrove Fractional Canopy Cover*, date not stated, [source](https://developers.google.com/earth-engine/datasets/catalog/projects_mangrovedatahub2_assets_CGMD-AFCC30)).

**Model:** scikit-learn RandomForestRegressor, 400 trees, depth 10, minimum leaf 2, eight lagged features (prior NDVI, NDMI, SAR, CO, month); [`scripts/train_model.py`](../../scripts/train_model.py). Dataset 94 monthly AOI records through Oct 2026, 90 valid; model fit on 66 and tested on last 12 complete observations. MAE **0.0306 NDVI**, RMSE **0.0413**, R² **0.488**; persistence MAE **0.0484**. This one temporal holdout is encouraging but small. There is **no labelled pixel classification accuracy**, no external spatial test and no confidence calibration. Evidence: [dataset validation](../../reports/dataset_validation.json), [evaluation](../../reports/model_evaluation.json). Model manifest is not approved for production external alerts: [manifest](../../models/ndvi_forecast_rf.manifest.json).

**Agents:** `MangroveGuardianAgent` coordinates acquisition, quality, features, forecast, rules, reporting and notification states. These are deterministic service stages, not autonomous LLM reasoning agents. Monthly schedule at day 5, 03:00 UTC, and startup reconciliation; subsequent retraining is code-supported. Evidence: [orchestrator](../../src/agents/orchestrator.py), [monitoring service](../../src/services/monitoring.py), [scheduler](../../scripts/run_scheduler.py). The UI polls about every 15 seconds; data still arrive on completed monthly windows, [dashboard](../../frontend/src/pages/Dashboard.jsx).

## Feasibility constraints and validation gates

1. **Spatial unit:** one AOI mean hides local loss; the [grid endpoint](../../src/services/grid.py) only returns geometry. Implement per-cell feature storage/inference and visualize cell-level uncertainty before claiming hot spots.
2. **Reference and tide:** a static 2023 mask excludes new mangroves and includes changed pixels; cloud/tide/phenology influence NDVI. Validate against FSI/NCSCM/GMW reference layers and tide-aware composites; see *Remote Sensing*, **2020**, [mapping-method study](https://www.mdpi.com/2072-4292/12/22/3758).
3. **SAR comparability:** separate Sentinel-1 orbit/pass and incidence-angle effects before interpreting backscatter changes; see Google, *Sentinel-1 GRD* [catalog](https://developers.google.com/earth-engine/datasets/catalog/COPERNICUS_S1_GRD).
4. **Model validation:** rolling-origin backtests; seasonal and no-change baselines; independent labelled events and negatives; incident-level precision/recall, false alarms per month, lead time, calibration, country/season breakdown. No accuracy claim until these pass.
5. **Operations:** test Earth Engine quotas, retry/idempotency, secure credentials, failure notification, data freshness, scheduler uptime and report delivery. Operational government/commercial usage may require paid Earth Engine configuration (Google, *Transition to commercial projects*, [policy](https://developers.google.com/earth-engine/guides/transition_to_commercial)).

**Standards:** GeoJSON for AOI/grid, REST/JSON API, UTC timestamps and provenance metadata are implemented by code. There is no claim of formal ISO 19115, STAC, OGC API or model-card compliance; those could be adopted later.
